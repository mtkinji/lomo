# Rule-based Screen Time and Contextual Unlock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the global personal Screen Time switches with independently owned rules, preserve the last-viewed Kwilt page after a shield handoff, and show an authority-aware bottom guide that permits a 20-minute temporary opening for authorized adults but never for children.

**Architecture:** Add a shared rule/read-model layer above the existing personal, Money, and family policy owners. Extend the native shield handoff to carry active restriction identities into one foreground coordinator, then render one root-level guide host after navigation restoration. Every temporary opening writes a rule-scoped override or domain-owned unlock and reconciles only the affected selection; family authority remains server-enforced.

**Tech Stack:** React Native, TypeScript, Zustand, React Navigation, Jest/jest-expo, Swift FamilyControls/ManagedSettings extensions generated by the Expo config plugin, Supabase Postgres RPCs.

---

## Product decisions carried by this plan

- One visible card represents one independently saved rule; selecting **A real step** and **Focus** creates two rules rather than two booleans on one global selection.
- The 10-minute value remains a Focus qualification threshold. Temporary opening uses one 20-minute default across personal, Money, and family policy.
- Adults may temporarily open rules they own or are explicitly authorized to manage. Children never receive or successfully invoke direct temporary opening.
- Shield entry never forces navigation. It preserves the warm route or restored cold-start route and overlays a root `BottomGuide`.
- Overlapping rules retain AND enforcement. A temporary opening is rule-scoped and may not claim the app is open if another active claim remains.
