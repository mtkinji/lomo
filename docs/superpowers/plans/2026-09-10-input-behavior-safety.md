# Input Behavior Safety Implementation Plan

> Execute inline, following regression-first debugging and the existing text-editing PRD. The shared checkout and current branch are retained per Andrew's repository instructions.

**Goal:** Improve focus reveal, keyboard clearance and text growth in real Kwilt workflows while preserving existing Return, Done, save, draft, navigation and rich-editing behavior; verify each behavior before expanding its use.

**Architecture:** Keep the existing input and host components. Hosts own visible bounds and parent scrolling; inputs retain native selection and text scrolling; features retain persistence. The visual-input task owns materials and the comprehensive caller migration ledger. This plan supplies behavior fixes and acceptance evidence, not a competing component family or dummy app.

**Tech stack:** React Native/Expo, existing KeyboardAwareScrollView, BottomDrawerScrollView, Input, Jest, iOS Simulator.

## Completion boundary

Do not declare app-wide compatibility from unit tests. Required evidence includes protected-flow characterization, reproduced failures and targeted regressions, actual keyboard-visible native interactions on representative screen and drawer hosts, and scoped local verification. Physical-device-only or unavailable platform scenarios remain explicitly unverified; do not promote the full PRD to accepted on weaker evidence.
