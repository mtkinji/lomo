# Diverge: Shared Content Home

Axis: notification-first versus feed-first versus capability-index-first.

## A. Warmer delivery inbox

Keep **Needs you** and **Recent**, but add sender identity and richer previews. This fits the current table and minimizes risk, but it still teaches that Home is mainly for actionable alerts. It fails when Explorations, recipes, and reflective check-ins become the majority of shares.

Primer check: passes, but answers too little of the expanded job.

## B. Feed-first receiving surface

Keep a compact **Needs you** section only when necessary, then show **Shared with you** as a chronological stream of rich, sender-led cards. Each card is rendered by its source capability and opens that capability. Sharing still begins outside Home; there is no generic composer or algorithmic ranking.

This extends the existing route and delivery projection without creating a second authorization system. It works when share types grow gradually through explicit adapters. It fails if every capability invents incompatible card semantics.

Primer check: passes. Only explicitly shared or capability-authorized objects enter the stream.

## C. Capability shelves

Home shows horizontal shelves such as Explorations, Goals, Games, and Recipes, each with a “Shared with me” entry. This makes retrieval obvious but weakens chronology and forces empty categories into the first release. It works at high content volume and fails while adapters remain sparse.

Primer check: passes, but risks dashboard-like containment and duplicated navigation.

## D. Shared rooms

Home organizes around persistent people-and-object rooms, with activity rings and contextual timelines. This could make long-running shared Goals and family trips feel alive, but it introduces a new room model that competes with capability ownership.

Primer check: privacy can pass, but the new container is unjustified for this release.
