# Diverge: Family recipe capture

Axis: transport-first versus intent-first versus conversational capture.

## A. Polish the current transport list

Keep Photo, Link/Text/Voice, and Blank as peers and improve labels. This has the smallest code change, but still asks Maya to translate her situation into Kwilt’s input mechanics.

Best when every source is already obvious. Fails when a family recipe could be a card, note, memory, or pasted message. System fit is high; job fit is only moderate.

## B. Intent-first capture

Ask whether this is a **Family recipe**, a **Recipe from the web**, or a blank start. Family recipe opens a single surface with photo first and paste/dictation immediately available. Web import opens directly to a URL. Both converge on the existing evidence-backed review editor and then Recipe Home.

Best when the user knows what the recipe means but not which import mechanic to choose. It fits current navigation, domain ownership, and capture infrastructure with no new model.

## C. Conversational intake

Open Chat and have Kwilt ask for title, ingredients, and steps. This can accept messy input, but turns a bounded capture into a transcript, makes completion less predictable, and risks anthropomorphic or over-helpful behavior.

Best for highly incomplete oral memories. Fails the reductive bar for ordinary cards, links, and complete notes.

## D. Recipe variants

Create one “Crepes” family with sourdough and standard children. This makes comparison explicit, but introduces hierarchy, inheritance, and editing questions unsupported by the current Recipe model.

Best for systematic test kitchens. Fails for a household that simply needs two findable recipes.

All retained concepts preserve capture-first behavior, private Recipe authority, and explicit review. None adds dashboards, streaks, forced setup, public sharing, or AI-authored family details.
