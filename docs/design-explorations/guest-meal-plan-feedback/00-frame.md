# Frame

Audience: aspirational family organizers. Representative persona: Maya.

Job-flow step 8, gather household input, is currently 3/5. The underserved edge
is a trusted person outside the activated Household. The first learning release
let that guest respond, but incorrectly made Share Plan a second place for Maya
to read feedback. The Plan already owns meal reactions and must remain the one
feedback-reading surface.

Constraint posture: `Fit the system`. Guest participation extends the existing
Plan reaction projection; it does not create a guest inbox, organizer summary,
or second feedback model.

The design challenge is:

> How might Kwilt let Maya ask one or more guests for useful, private meal input
> without making them install the app, creating Household membership, or
> making her reconcile feedback in more than one place?
