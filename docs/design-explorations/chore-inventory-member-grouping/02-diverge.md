# Diverge: Chore Inventory Member Grouping

Axis of variation: automatic structure versus explicit user control.

## A. Always grouped

The caregiver inventory always renders Charlie, Olive, then Household sections. This is the lowest-chrome option, but removes the continuous list and gives no visible explanation for why the list is structured this way.

- Best when: member grouping is universally useful.
- Fails when: a caregiver wants one compact inventory or expects the existing control rail to own view changes.
- System fit: medium; simple rendering, but no affordance.

## B. Group control with Member as the default

Add the standard `layers` control beside the existing funnel. Its immediate menu offers **Member** and **None**. Member is the default, producing named sections in member order with Household last. Grouped rows omit the redundant assignee pill; the flat view restores it.

- Best when: the described household scan should work immediately but remain reversible.
- Fails when: the menu grows into a saved-view builder.
- System fit: strong; reuses the inventory rail and current assignment model.

## C. One combined View menu

Replace the funnel with one labeled menu containing both filter and grouping choices.

- Best when: the control rail must be minimized at any cost.
- Fails when: filter and grouping become hard to distinguish, discover, or report accessibly.
- System fit: weak; collapses two different operations and departs from the To-dos inventory grammar.

All three preserve Activity-backed Chores, capture-first behavior, and the calm-UX bar. None adds a dashboard, score, ranking, or new shared data.
