# Diverge: Unified Chat local-first inference

## A. Shadow-only evaluation

Run local generation beside the cloud response and compare later. This is safest for quality measurement, but it spends more money and does not improve the user's current latency.

## B. Broad local Chat replacement

Send every ordinary general-purpose turn to the device. This maximizes theoretical savings, but local context limits, current-information gaps, and unpredictable quality make it too broad for the first release.

## C. Typed local-first task router

Use authored responses for deterministic social turns and Apple Foundation Models only for narrowly classified text transformations and small ideation. Fall back to the existing cloud route on any uncertainty or failure.

This best fits the job because it produces real savings now while preserving the stronger model and capability contracts for the work where quality and authority matter most.
