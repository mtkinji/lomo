# Yes-And: Exploration Recap

## Original idea

Quietly accumulate named Place discoveries and show one recap instead of interrupting the outing.

## Expanded value

1. Keep a silent discovery ledger for the active Explore session.
2. Resolve a bounded sample of route points only after the route returns to the foreground.
3. Automatically retain high-confidence named parks, trails, overlooks, summits, and landmarks as visit metadata on canonical Places.
4. Present one route-ordered recap with easy correction rather than a confirmation queue.
5. Send at most one privacy-safe local notification for everything unseen when outings complete in the background.
6. Keep place names off the lock screen unless the user explicitly changes that preference.
7. Dedupe places already collected so familiar territory does not repeatedly celebrate.
8. Leave family aggregation for authenticated, individually consented sharing.

## Frame recommendation

Run the loop with the expanded frame: Exploration Recap is a quiet reflection surface over an Explore session, not a notification feature or a second Place model.
