# Grocery List and fulfillment UI contract

Job: When the household is preparing to shop, the user needs to see and update one familiar grocery checklist, so they can cover what they already have and fulfill only what remains.

Authority chain: Andrew's explicit list-first and direct-fulfillment decisions -> `03-converge.md` Grocery Flywheel -> Kwilt UI constitution -> Candidate inventory/list and persistent-decision-region patterns -> existing Recipe ingredient checklist treatment.

Three-second read: This is a grocery checklist; checked items are covered, carted items are labeled without being checked, and the bottom action begins online shopping. After a store is selected, fulfillment is an automatically populated handoff cart: `Cart` in the header, the retailer selector at top right, then product thumbnail, package, current store price, retail quantity, Edit, and Remove. A full-width bottom container shows the estimated item subtotal and the one retailer handoff action.

Primary action: `Shop online` on the first pass, then `Shop N remaining` only after a retailer has acknowledged some items in its cart. Inside the handoff cart, `Add N items to [retailer]` confirms the current product/package quantities, adds them to the retailer cart, and opens that cart directly. Pickup scheduling, fees, substitutions, payment, and checkout happen once, at the retailer. Entering fulfillment is the user's explicit signal that the current remainder is ready for retailer matching; no separate list-review confirmation is required.

Primary information: Grocery items grouped by store section, their quantities, and covered state.

Secondary information: The contributing Meal Plan in the familiar top-right Plan pill, offline/sync state, a compact selected-store selector, and quiet per-item `In Smith's cart` receipts.

Reveal later: Checked-item review and list maintenance live in the header menu; item editing remains on long press; Kroger-family store choice and product matching appear in fulfillment. After selection, only the retailer banner and a down chevron remain in the cart header; the full address and alternate stores return when that selector is tapped. Choosing a store immediately starts product matching; there is no separate explanation or confirmation step. Best matches populate the reversible handoff cart with one retail package each. `Edit` reveals alternative products, `Remove` excludes a line from this retailer pass, and quantity changes count retail packages rather than recipe units. Kroger authorization occurs only when adding the prepared cart. The selected retailer owns pickup timing and fees, substitutions, payment, checkout, and the final total. Suggestions such as remembered staples may appear before handoff only when they are explainable and can be accepted directly into the current list and matched cart; they must not create a second review loop or masquerade as paid upsells.

Scan order: Groceries title and Plan context -> grouped checklist -> `Shop online` or `Shop N remaining` dock action.

Must not add: Introductory count copy, a separate `Review what I already have` button, a `List looks right` confirmation, `Choose products` above a cart, product checkboxes/radios in the default cart, repeating Need/Have labels, repeating Why actions, green CTA styling, mixed-cart optimization, a full catalog of alternatives in the default scan, or a second durable Kwilt list/basket object.

Reuse map: Check mark and strikethrough -> `RecipeIngredientChecklist`; Plan context -> shared `MealPlanHeaderAction`; low-frequency review -> `DropdownMenu`; direct preferred-store fulfillment -> `KrogerCart`; persistent handoff -> a safe-area-aware full-width footer container and Sumi `primary` Button.

Nearest precedent: Recipe Home ingredients provide the exact checked-row treatment. Meals provides the exact Plan pill. Recipe inventory provides the floating dock geometry. Groceries differs by persisting checklist changes and by giving the dock a fulfillment consequence.

External exemplar ledger: Apple Reminders Groceries, reviewed 2026-08-09 -> preserve direct grouped checklist and shared completion semantics; translate into Kwilt's Recipe checklist and household authority; reject Apple-specific list chrome. AnyList, reviewed 2026-08-09 -> preserve Recipes and Plan as inputs to an independently useful list; reject its product styling. Instacart and Kroger carts, reviewed 2026-08-09 -> preserve product/package/price, retail quantity, Edit or replacement, Remove, estimated subtotal, and fulfillment context; translate into a reversible pre-handoff draft; reject checkout promises the public Kroger Cart API cannot substantiate. Instacart and Walmart order status, reviewed 2026-08-09 -> preserve truthful preparing, ready-for-pickup, out-for-delivery, and delivered concepts for a later provider-authoritative slice; reject provider status claims without an order-status contract.

Behavior sources: Check toggles are Andrew's explicit already-have/purchased model and the current grocery offline queue; they do not carry into the cart. Direct one-store fulfillment is Andrew's explicit decision and the Grocery Flywheel. One Kroger authorization supports Kroger-family banners; Smith's is the current local store, not a separate connection. Store search and matching precede authorization. Store-specific Product API results provide product imagery, regular/promo item prices, and curbside product availability at match time. Kwilt may total those observed item prices as an estimate, never a quote. The public Cart API accepts UPC, retail package quantity, and pickup modality but does not return cart contents, a quote, fees, taxes, time slots, or order evidence. A provider acknowledgement creates a separate per-item cart receipt and removes that item from the next matching pass without checking it off. The retailer owns substitutions, scheduling, payment, checkout, and current order status.

Unresolved decisions: Provider-authoritative purchase, replacement, delivery, pickup, cart removal, and abandoned-cart states are not currently available from the Kroger cart handoff. Do not infer them from cart addition. Amazon and a second-retailer pass remain later work.

Required states: Loading; empty list; populated review-needed list; covered and needed items; offline and queued changes; stale list after Plan revision; no remaining items; fulfillment preparation failure; Smith's disconnected, location missing, matching, cart-added, and plain-list fallback.

Proof path: iPhone Simulator -> open global navigation -> Food -> Groceries -> press `Shop online` -> choose a Kroger-family store without an account connection step -> observe matching begin immediately -> review individual matches -> add approved products -> authorize with Kroger only when required -> confirm that acknowledged items read `In [banner] cart` while unchecked and only the remainder enters the next pass.
