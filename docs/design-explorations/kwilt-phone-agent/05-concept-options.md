## Three materially different approaches

Axis: what the user expects the agent to know and leave behind. Voice/text modality remains a separate open choice.

### A. A thinking line

Illustrative moment: Andrew is on a walk and wants to work through a new idea.

> Andrew: “I have ten minutes. Help me work out why this product idea feels incomplete.”
> Agent: “What would someone be able to do if it worked?”

The agent can be useful with context supplied during the conversation. The result is clearer thinking and, if requested, a short saved conclusion. No account actions are required.

- Best when access and conversational rhythm are the main friction.
- Fails when Andrew expects it to know the ongoing work already.
- Nina fit: good for ordinary-language expression; limited continuity.
- System fit: a general conversation need not create an Arc, Goal, Activity, or Chapter. Do not force capture into product objects.
- First test: a real conversation through the intended access surface, with an explicit place for the requested written result.
- Test limit: proves neither external conversation continuity nor Kwilt tool use.

### B. A continuation line

Illustrative moment: Andrew leaves his desk mid-project and wants to keep thinking about the same problem.

> Andrew: “Let's continue the Phone Agent discussion. I think the important part is being able to reach the same conversation.”
> Agent: “The open question was whether you want a new conversation or continuity with the tools you already use. What changed your mind?”

The promise is a chosen thread that survives a change of interface. It must resume the correct context and leave the result where Andrew can find it later.

- Best when the work already exists and repeating context destroys the value.
- Fails when a generic agent impersonates continuity, or the setup takes longer than retelling the problem.
- Nina fit: strongest match for help without retelling.
- System fit: reuse an owned thread when available; integration with an external product needs evidence. A manually supplied brief is an explicitly limited substitute, not proof of live synchronization.
- First test: one selected thread, authorized context, a real phone conversation, and a durable recap associated with that work.
- Test limit: a manually seeded context test measures the value of context, not automatic access to ChatGPT history or two-way thread synchronization.

### C. A Kwilt action line

Illustrative moment: Andrew remembers something he needs to do while his usual interface is inconvenient.

> Andrew: “Add a to-do to call the school tomorrow.”
> Agent: “Added ‘Call the school’ for tomorrow.”

That final response is allowed only after the action is verified. If the user instead requests a consequential or ambiguous change, the agent obtains the appropriate clarification or review and accurately describes pending work.

- Best when the desired outcome is a real change in Kwilt.
- Fails when conversation merely produces advice or sends the user back to reconstruct the request in the app.
- Nina fit: strong for capture and controlled action.
- System fit: existing capability operations and receipts own writes. Activities remain first-class without mandatory Goal/Arc selection. No parallel phone-only planner.
- First test: correct account authentication, one useful capability, and a visible authoritative result in Kwilt.
- Test limit: one successful operation does not prove broad account control, device-only actions, or external AI continuity.

All three concepts exclude anthropomorphic claims, unsolicited outreach, forced commitments, dashboards, and automatic Arc/Goal assignment. They should reduce effort in an existing moment rather than invent a new daily ritual.

## Proposed learning protocol after selection

Use one coherent concept in five naturally occurring moments. Five is a practical qualitative checkpoint, not a statistical validation target.

Record only:

1. What triggered the attempt?
2. How much setup or retelling did it require?
3. Did the interaction produce the intended outcome?
4. Was the result available where expected afterward?
5. Would Andrew choose this way again for that situation, and why?

Compare against the way Andrew would actually handle the same moment today. Avoid inventing a baseline or requiring artificial daily usage. Distinguish failures of access, conversation, context, and action so one does not masquerade as another.

Proposed decision rule: continue when Andrew voluntarily returns for the same class of situation and the intended result is dependable. Revise when useful conversations consistently fail on one fixable boundary. Retire or change the frame when the normal workflow is easier or the need does not recur. Agree on the concrete success conditions for the chosen concept before building it.
