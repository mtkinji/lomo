# Diverge: Focus Widget

## A. Next-up Focus

The widget starts Focus on the next scheduled Activity. This keeps all Focus time attached to work, but silently guesses the user's intention and fails when no next Activity exists.

## B. Standalone preset

The user configures 10, 25, or 50 minutes in the widget gallery. One tap starts an explicitly unlinked Kwilt Focus session. While active, the widget shows the live countdown and opens the in-app controls.

## C. Focus launcher

The widget opens an app sheet for duration and Activity selection. It is flexible and truthful, but it does not deliver the requested whenever/one-tap behavior.

All three reuse the existing Focus runtime. Only B removes setup without making a false association.

## 2026-08-05 refinement: where the decision belongs

### A. Native widget configuration

Duration and audio live in Edit Widget and a tap starts immediately. It is fast
after setup, but buries meaningful choices in a maintenance surface and makes them
easy to forget.

### B. In-app start drawer

The widget opens one compact drawer with two sections: How long and Audio. The user
makes both choices in context and presses Start. It adds one step, but the step is
the point: a calm, visible commitment immediately before Focus begins.

### C. Automatic start

The widget starts with saved or randomly chosen values. It is the fewest taps, but
either repeats an old decision invisibly or takes agency away at the moment audio
begins.

All three preserve the four-object model and capture-first posture because they
only configure an explicitly standalone Focus session. B best fits the corrected
design challenge without dashboards, pressure, or new persistent concepts.
