# Yes-And: First-Install Success Across Kwilt

## Original idea

First install should identify or honor the success a person came to Kwilt for, then route them into
the appropriate capability-owned journey; today's Arc/Goal onboarding remains one excellent
destination rather than the universal funnel.

## 1. Preserve explicit context when it actually survives

**Yes, and what if Kwilt could preserve a verified invite, live deep link, or interrupted path when
one actually reaches the app, without making first-install strategy depend on knowing the door?**

- Serves: `jtbd-move-the-few-things-that-matter`, `jtbd-trust-this-app-with-my-life`
- Job elevation: First install becomes a continuation of the person's real decision rather than a
  reset into Kwilt's internal product model.
- New value: An invite, live deep link, shared object, trustworthy restore target, or interrupted
  path can bypass generic orientation when that context is genuinely present. A normal first launch
  is still assumed to have unknown intent; App Store interest or campaign provenance is not treated
  as available without an explicit implemented handoff.
- Cost delta vs. original: medium
- Anti-pattern check: pass if only explicit, inspectable context affects routing. It fails if Kwilt
  infers sensitive needs from private data, demographics, or opaque advertising profiles.

## 2. Give every person one true sense of Kwilt before specializing

**Yes, and what if the universal part of onboarding were a short, illustrated statement of what
kind of relationship Kwilt offers, rather than a list of capabilities or one capability's
philosophy?**

- Serves: `jtbd-trust-this-app-with-my-life`
- Job elevation: A person can recognize that Recipes, Money, Goals, and Chores belong to one calm,
  private Kwilt without first learning the suite.
- New value: The strongest parts of the existing full-screen Welcome experience can remain as a
  consistent brand and trust moment even when the next step varies by intent.
- Cost delta vs. original: low
- Anti-pattern check: pass if this is one brief, concrete orientation moment. It fails if it makes
  broad life-improvement promises, turns into a product manifesto, or delays a known-intent path.

## 3. Ask about desired success, not capability selection

**Yes, and what if an unscoped person chose the outcome they want in ordinary language instead of
choosing among Recipes, Chores, Money, Goals, and other product nouns?**

- Serves: `jtbd-move-the-few-things-that-matter`, `jtbd-carry-intentions-into-action`
- Job elevation: The choice reflects the user's demand—such as making dinner easier, getting the
  house under control, understanding spending, or making progress on something important—rather
  than testing whether they understand Kwilt's architecture.
- New value: The same outcome vocabulary can drive a visual walkthrough, a compact choice surface,
  an Agent exchange, campaign links, and later analytics without exposing a new user to the full
  capability map.
- Cost delta vs. original: medium
- Anti-pattern check: pass if the options are concrete, currently deliverable, skippable, and few
  enough to understand. It fails if they become a life-category survey, personality quiz, or
  exhaustive capability catalog disguised as user language.

## 4. Turn the existing walkthrough pattern into a flexible orientation grammar

**Yes, and what if the full-screen interstitials could compose only the moments relevant to this
arrival, while retaining their current illustration, color, pacing, and one-action clarity?**

- Serves: `jtbd-trust-this-app-with-my-life`, `jtbd-carry-intentions-into-action`
- Job elevation: Kwilt preserves an onboarding experience Andrew already likes while making its
  sequence responsive to why the person came.
- New value: A known-intent arrival might see Welcome and one relevant capability promise; an
  unscoped arrival might see Welcome and an outcome-selection moment; a returning user may need no
  interstitial at all. Existing illustrations can be reused wherever they remain truthful.
- Cost delta vs. original: medium
- Anti-pattern check: pass if the sequence stays short and each screen changes the person's
  understanding or next action. It fails if modularity becomes permission to assemble longer
  tours, if every capability demands a slide, or if new illustrations are produced before a real
  communication gap is identified.

## 5. Let each chosen path inherit the quality of the original Kwilt journeys

**Yes, and what if every route from first install had to end in one real native result, with the
same conceptual completeness the Arc/Goal path already demonstrates?**

- Serves: `jtbd-carry-intentions-into-action`, `jtbd-trust-this-app-with-my-life`
- Job elevation: Onboarding becomes successful use rather than completed education.
- New value: The user who came for a recipe reaches a recipe they can save, cook, or use; the user
  who came for chores creates or accepts a real responsibility; the user who came for Money reaches
  account-backed understanding; the user who came for growth still creates an Arc, Goal, or To-do.
- Cost delta vs. original: high
- Anti-pattern check: pass if capabilities own setup, permission, mutation, recovery, and proof of
  value. It fails if the shell simulates success with sample data, ends at an empty home, or claims
  a capability result before the required connection or authority exists.

## 6. Make interruption and resumption part of first-install quality

**Yes, and what if a person could leave during orientation or capability setup and return to the
exact honest next step without replaying the whole first-time sequence?**

- Serves: `jtbd-trust-this-app-with-my-life`, `jtbd-recover-when-i-drift-from-an-arc`
- Job elevation: Kwilt respects that setup involving finances, family authority, imports, or
  reflection may not fit into one uninterrupted session.
- New value: First-install state can distinguish universal orientation, declared intent, chosen
  path, capability progress, and achieved first value. The app can resume without pretending an
  unfinished capability is globally complete or globally unstarted.
- Cost delta vs. original: medium
- Anti-pattern check: pass if the state remains invisible and serves recovery. It fails if users
  see a setup checklist, completion pressure, streak framing, or repeated prompts to finish a
  capability they no longer care about.

## 7. Make recommendation eligibility a product-truth boundary

**Yes, and what if first install could recommend only success paths whose native capability is
ready to fulfill the promise in the current build, device, role, region, and account state?**

- Serves: `jtbd-trust-this-app-with-my-life`, `jtbd-stay-in-control-of-ai-actions`
- Job elevation: Kwilt's guidance becomes trustworthy because every visible option is actionable,
  not because the suite appears comprehensive.
- New value: A capability can exist in the app or full map without being promoted during first
  install. Readiness, eligibility, and setup disclosure become inputs to routing instead of hidden
  caveats after selection.
- Cost delta vs. original: medium
- Anti-pattern check: pass if unavailable paths are omitted or explained truthfully when explicitly
  requested. It fails if first install advertises coming-soon concepts, chooses a path that cannot
  succeed, or uses readiness labels as user-facing feature promotion.

## 8. Measure the result by chosen-intent success

**Yes, and what if onboarding success were measured by whether the person reached the result they
chose, rather than whether they completed a universal sequence?**

- Serves: `jtbd-move-the-few-things-that-matter`, `jtbd-trust-this-app-with-my-life`
- Job elevation: Product learning focuses on whether Kwilt helped, not whether users complied with
  setup.
- New value: Kwilt can compare recognition, route selection, time to native first value,
  interruption, resumption, correction, and voluntary return by intended outcome. A Goals path and
  a Recipes path can have different first-value evidence without becoming incomparable.
- Cost delta vs. original: medium
- Anti-pattern check: pass if instrumentation uses bounded event metadata and capability-owned
  proof. It fails if private recipe, chore, financial, family, or identity content is captured to
  optimize onboarding, or if completion rate becomes pressure to remove necessary trust steps.

## What the expansion reveals

The frame is the right size, but **routing** is only the center of the strategy, not the whole
strategy. A coherent first-install system has five responsibilities:

1. **Assume intent is unknown** - make the ordinary first-launch experience work without
   acquisition metadata or deferred linking.
2. **Establish universal bearings** - say only what every new person needs to understand about
   Kwilt, potentially through the existing full-screen and illustration language.
3. **Resolve unknown intent** - help an unscoped person choose a desired success in ordinary
   language without surveying their life or presenting a capability catalog.
4. **Handoff to native first value** - let the selected capability own setup and produce a real
   result.
5. **Remember and resume honestly** - distinguish orientation, chosen intent, capability progress,
   and achieved value so interruption does not break the experience.
6. **Honor verified context opportunistically** - bypass generic steps only when an actual invite,
   live link, restore target, or interrupted path survives into the app.

Capability readiness is a dependency of this system: Kwilt cannot offer a first-install path merely
because a capability exists. It is not the first design problem to solve, but it becomes the
truthfulness filter on whatever strategy wins.

## Anchor coverage

No new JTBD node is needed. “Help me discover Kwilt” is still product language, not a standalone
user job. The strategy is covered by:

- `jtbd-move-the-few-things-that-matter` for desired-success recognition and routing;
- `jtbd-carry-intentions-into-action` for reaching native first value;
- `jtbd-trust-this-app-with-my-life` for calm orientation, truthful choices, permissions, and
  recovery;
- `jtbd-get-help-without-retelling-my-life` for carrying entry intent and resuming correctly; and
- `jtbd-stay-in-control-of-ai-actions` for bounded Agent assistance when ambiguity needs help.

## Frame recommendation

**Run the design-thinking loop with the original frame, clarified as an intent-to-success
first-install system.**

Do not broaden this phase into all long-term capability adoption, cross-selling, or re-engagement.
First solve the bounded path from arrival through one native first success. Capability onboarding
and readiness should be designed as the contracts that make those routes honest, then Recipes can
be the first detailed application.

## Review question

Should divergence compare materially different ways to resolve the default **unknown-intent** first
launch, while treating verified known intent as an optional bypass and preserving the existing
full-screen walkthrough and illustration language as reusable material rather than a required fixed
sequence?
