# Yes-And: Goal Progress Table

Original idea: Let a Goal contain the checkable table shape Charlie used to represent Utah's 29 county high points.

**Yes, and what if it could...** preserve the existing note by accepting pasted rows instead of requiring re-entry?

- Serves: `jtbd-trust-this-app-with-my-life`
- Job elevation: Moving into Kwilt does not mean losing work or representation.
- New value: The workaround becomes the import path.
- Cost delta vs. original: low
- Anti-pattern check: pass; deterministic parsing avoids anthropomorphic AI and surprise transformation.

**Yes, and what if it could...** let each Goal define the data columns its To-dos need?

- Serves: `jtbd-move-the-few-things-that-matter`
- Job elevation: The user sees the context that makes each To-do meaningful without forcing one universal task schema.
- New value: County / High point / Elevation can become Book / Author, Trail / Distance / Gain, or another Goal-specific shape.
- Cost delta vs. original: low
- Anti-pattern check: pass; it protects the four-object model.

**Yes, and what if it could...** make each named outcome checkable without turning progress into a percentage?

- Serves: `jtbd-move-the-few-things-that-matter`
- Job elevation: Progress stays concrete and place-based rather than becoming a score.
- New value: The remaining counties are visible at a glance.
- Cost delta vs. original: low
- Anti-pattern check: pass; no dashboard or identity score.

**Yes, and what if it could...** carry useful reference facts such as elevation, route class, or date visited?

- Serves: `jtbd-trust-this-app-with-my-life`
- Job elevation: The Goal becomes the reliable shared reference, not merely a title.
- New value: Two additional named columns support many real-world goal shapes.
- Cost delta vs. original: medium
- Anti-pattern check: pass when capped; arbitrary spreadsheet behavior would fail the calm UX bar.

**Yes, and what if it could...** preserve the normal To-do contract underneath the table?

- Serves: `jtbd-carry-intentions-into-action`
- Job elevation: Checking a summit behaves exactly like completing any other To-do and participates in existing undo and progress behavior.
- New value: The table is a view, not a parallel completion system.
- Cost delta vs. original: low
- Anti-pattern check: pass; capability ownership stays with Activities.

**Yes, and what if it could...** become a reusable Goal template for finite adventures, reading lists, visits, and collections?

- Serves: `jtbd-move-the-few-things-that-matter`
- Job elevation: More outcome-based Goals can retain the shape that makes them meaningful.
- New value: The capability generalizes without becoming a spreadsheet product.
- Cost delta vs. original: high
- Anti-pattern check: pass only after real repeated demand; premature template galleries would add setup and clutter.

## Frame recommendation

**Run design-thinking-loop with an expanded frame.** The evidence supports a Goal-owned custom-column view over its To-dos, not a separate checkable block. Templates remain a later adjacency.
