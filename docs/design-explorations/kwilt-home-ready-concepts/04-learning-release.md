# Learning release: a complete connected visit

## Concept to build

Open Home, recognize your people, enjoy their moments, acknowledge a contribution, follow a useful source action, share something yourself, and return later to a saved moment.

## Capability delta

Today the functional foundation and the first mockup do not provide a complete people catch-up, response-summary, expressive-content, saved-library and continuity system. After the defined releases, all eight concepts have real destinations and usable lifecycle states. Familiar-looking icons alone do not count as delivery.

Still outside this release: social DMs, ephemeral Stories, video, shared scrapbooks, new picnic/event invitation infrastructure, automatic personal posts, and expanded child access. They remain independent roadmap opportunities, not silent scope promises.

## User experience and release bundles

| Bundle | Real end-to-end experience | Concepts | Evidence required |
|---|---|---|---|
| 1. Moments and participation | Read mixed photo/text/goal/chore posts; see a real invitation; open source; respond; create with a clear audience; return to position and recover failures. | C3, C4, C5, C8; C2 conversation; C7 | Populated native walkthrough, source authority checks, interruption/retry and media testing |
| 2. People and conversation | Enter a finite catch-up, see real appreciation names and one reply preview, return to original context. | C1; remaining C2 | Authorized summary/seen tests and two-account native response/visibility proof |
| 3. Keep and revisit | Save a moment immediately, organize optionally into private collections, refind and distinguish saved post from saved Explore place. | C6 | Private-library lifecycle, revocation, collection deletion and native retrieval tasks |

Each bundle should feel complete on its own; all eight remain defined and retained. The integrated prototype used for evaluation should eventually include all three bundles with shared fixture identities and stable post IDs.

## Existing product relationship

Enhance `SharedLifeFeed`, composer, conversation, source delivery cards and current media/repository modules. Reuse existing `ProfileAvatar`, canvas/list, drawer, refresh, theme and celebration primitives. Add only the state/projections the concepts actually require. Source capabilities retain original commands and access control; Home owns presentation, posts and their social conversations.

## Buildable slice

Must be real: publication, authorized summaries, seen state, saves/collections, source-route availability, draft persistence, local response reconciliation, account switching and access removal. Testing a static screenshot cannot validate these.

Can be temporary: a local fixture harness with fictional accounts/posts, a development-only entry for failure simulation, and manual research notes. Runtime backend tests use disposable accounts and authorized scenarios; no fictional activity is inserted into Andrew's household.

Fixture content: landscape picnic album, portrait photo, six-line-plus text story, completed goal with reflection, pending/approved/mixed chores, actual supported Goal invitation, new reply, failed second image, saved collection, deleted post, offline state, and no-connections state.

## Release channel

Local native build first for Andrew's full-flow review; then signed TestFlight for invited household participants; then existing feature-gated limited production exposure once each bundle's proof is complete. Preserve the distinction between source tests, deployed RPC proof, Simulator appearance, signed-device behavior and actual rollout.

## Brand-goodwill guardrails

Use truthful people/content/counts, name the actual post audience, preserve voluntary personal posting, and explain pending actions. No decorative unread rings, fake reactions, unsupported invitations, hidden publishing or surprising onward sharing. Photo quality must not imply only polished outings belong; the fixture set includes ordinary words and contributions.

## Reversibility

Use existing Home gating for presentation; make schema changes additive and old-client compatible. A layout rollback must not erase posts, drafts, private saves or collections. Server-controlled visibility remains active even when new UI is disabled. Draft/publication state reconciliation must work across app restart and version changes. New infrastructure requires backend checks before rollout; no migration is being executed during this design loop.

## Permanent product threshold

Users can complete the core tasks without help, understand audiences and source states, recover interruptions, and report that Home helps them feel included. Revise an individual concept when its bet fails; don't interpret more scrolling or more chores as evidence of better connection.
