# Evaluate Home activation

## Learning questions

1. Do people encounter and understand explicit invitations to useful setup steps without first discovering those features? Can they then resume without repeating onboarding?
2. Can people distinguish steps they can take from steps waiting on someone or another device?
3. Is setup progress clear without making unrelated capabilities feel compulsory?
4. Does a first useful outcome lead to independent return to the capability?
5. Does the first real post remain apparent when guidance is present, while needed setup survives its arrival?
6. Can a recipient reach a useful authorized action without repeating organizer setup?
7. Can users describe the outcome and next steps, resume Later, and find the result again without Home guidance?
8. Can an established solo user feel settled while the feed is empty?

## Initial review

Use the scenario matrix in the brief for local walkthrough, then a proposed 6–8 moderated internal sessions spanning solo-first, organizer, invited adult and returning-user cases. This is comprehension evidence, not a statistically meaningful retention experiment.

Advance to a small cohort only if every represented role/device privacy case passes, every promoted continuation reaches its owner result, no participant mistakes device connection for applied controls, and at least 80% can predict both the next action and who must take it without explanation. Inspect each confusion; do not average away authority or truth failures.

## Outcome ladder

Keep distinct: orientation exit; selected path; setup checkpoint; owner-confirmed first value; extended first-cycle payoff; later independent use; voluntary shared participation. Food plan receipt and a reviewed grocery list are different evidence. Money foundation and a subsequent trusted decision are different evidence. Goal created and Goal completed are different evidence. Chat user-message sent is an engagement event, not evidence of an answer's usefulness.

## Proposed instrumentation

Reuse existing capability IDs, completion receipts and analytics where possible. Proposed Home events: invitation shown, accepted, deferred, declined; guidance continued, hidden, overview opened. Deduplicate the same invitation across its source surface and Home. Include only contract/path version, presentation state, source entry class, reason code, release cohort and allowed coarse context. Never include names, child or device identifiers, recipients, account details, amounts, photos, task titles, invitation tokens or chat text.

Measure invitation-to-start, start-to-owner-result, and resume-to-owner-result conversion, plus authorized recipient first contribution separately from membership acceptance and later independent capability use at day 2 and within 7 days, separated by new/returning entry, chosen path, setup state and release cohort. Pending-other-person time is not active setup time. Respect the existing analytics consent/exclusion policy and exclude internal accounts from production inference. Event names and payloads are proposals until reviewed; no telemetry is enabled by this document.

## Decision rules

- Proceed when participants can resume accurately, distinguish readiness, and keep using the actual result; use a predeclared sample window and minimum cohort size before quantitative rollout decisions.
- Revise when clicks rise but useful outcomes do not, the overview feels like obligation, or people cannot find posts.
- Simplify when repeated deferrals cluster at the same step or users do not want cross-capability guidance.
- Hold promotion on unknown owner facts, stale authority, account leakage, unsupported routes, misleading progress or a failed physical-device promise.
- Retire the prominent region if most intended users prefer the native capability entry and Home adds no continuity value; retain the voluntary resume page only if useful.

Next action after design review: implement the smallest complete rehearsal, collect native evidence, then finalize the quantitative cohort decision rule from baseline volume. No invented baseline, usage result or retention lift is claimed.

## Capability discovery and placement comparison

Compare the same offer in a persistent Home region, contextual native card and on-load bottom guide. Observe discovery, return findability, competing feed use and perceived interruption. Include an established single-capability user with unfinished optional work. Measure previously unused capability first value separately from current-capability continuation; no variant wins merely by increasing prompt clicks.
