# Learning release: resume one useful path from Home

## Concept to build

An adult receives an explicit invitation into relevant setup, can leave a chosen setup or first-use path, return to Home, see a short visible outcome sequence, one accurate recommended action and scoped progress, and continue in the real capability while shared life appears alongside it.

## Capability delta

Today: Home cannot carry chosen onboarding intent or distinguish a relevant pending household step from an ordinary empty feed.

After the slice: Home and native onboarding agree on the same state; personal value can proceed without family participation; waiting, dismissal and first payoff change guidance predictably.

Still excluded: new universal onboarding design, automatic invitations/publication, child Home, global household completion score, general daily task prioritization.

## User experience

Rehearse the accepted Welcome/reel, choose Meals, keep a real meal, leave before compiling groceries, return to Home, and continue to the real list. Rehearse Money with real owner state and an actual supported setup path. After a real meal-plan result, show the explicit household-sharing invitation before the user has opened Household. Accept it, send through the existing owner UI, and verify truthful waiting. After adding a child, offer the eligible access/device setup explicitly, then verify each next prerequisite. Add a real authorized post and verify that it is readable while setup remains incomplete.

The production-shaped UI uses gray Home, one recommended action with quiet milestone rows, and the optional Getting started page. The Developer Tools wrapper explains when native work creates real data. Static examples may test visual states but cannot prove readiness or first value.

## Existing product relationship

Enhances Home and capability-onboarding continuity. Reuses owner checkpoints, typed handoffs and ordinary data. Preserves current production entry and release gates. The entire cross-capability concept is specified; sequencing the adapters below is an implementation order, not a reduced replacement concept.

## Buildable slice

Must be real:
- Correct account/rehearsal scoping and hydration, source adapters, eligibility, dismiss/resume behavior, and reading-anchor preservation.
- Meals path through real plan and grocery payoff, including optional sharing.
- Money owner checkpoints, plan evidence, cancellation and recovery. If connected-account readiness cannot be established, do not substitute demo data as proof.
- Shared source/Home invitation identity, explicit triggers, benefit copy, acceptance and scoped dismissal; ignored offers remain findable.
- Household membership/invitation projections and role-safe next actions; invite recipient and organizer experiences remain distinct.
- Device connection as a separate fact. Full child Screen Time continuation requires separately verified native enrollment, authorization and applied-policy receipts.
- Empty, mixed and established Home, plus skip-tour and returning-user cases. Independently verify active/settled guidance against empty/populated feed.
- Actual recipient handoff to authorized content, including auth/install continuation or honest recovery; validate both sender and recipient.
- Later as a parked visible row, distinct Not for me/help, and finding the result again without the guide.

Can be thin: deterministic local adapter registry and local-only presentation preferences for rehearsal, declared as such. No AI ranking needed.

## Release channel and gates

1. Local hidden rehearsal on current native app. Exercise every state in the scenario matrix; visual examples remain labeled examples.
2. Internal TestFlight with clean, invited and returning adult accounts; real multi-account household actions. Screen Time requires the appropriate physical devices and supported grant/entitlement combinations.
3. Production-hidden Home continuation for eligible supported paths. It can coexist with current first-install onboarding by reading owner facts, but cannot promote the new universal reel.
4. Default Home shell entry for the new onboarding cohort only after the separate capability-routed onboarding promotion contract passes. Promote together at this seam; do not switch the global drawer default for all existing users.

Each production-visible adapter needs an executable route and truthful full path. Keep unsupported discovery entries absent. Already-active capability failures retain their owner recovery route and honest state; gating never hides required recovery.

## Reversibility and brand protection

Hide guidance without changing capability data, household membership, completed first-value records or the feed. Do not store setup as posts. Preserve native progress on dismissal and rollback. A disappeared local preference cannot grant authority or manufacture completion. Production preference syncing, cohort enrollment and analytics are separate reviewed implementation work.

## Permanent product threshold

People predict the next step and actor, resume real work, recognize pending vs ready, see real posts without setup obstruction, and stop seeing guidance when they dismiss or finish it. Evidence must cover solo, family and returning use; a checklist-completion uplift alone is insufficient.
