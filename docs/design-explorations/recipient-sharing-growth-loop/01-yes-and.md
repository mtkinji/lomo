# Yes-and: Recipient Sharing Growth Loop

The offered idea is not merely a better Friend invitation. It is a recipient-side participation system that can turn a private share into useful value before asking for a durable commitment.

## Aspirational adjacencies

### 1. A typed recipient envelope across capabilities

- Expansion: every share declares its object kind, safe preview, guest actions, identity requirement, app requirement, expiry, and revocation behavior.
- Job elevation: the recipient learns one consistent consent grammar instead of decoding each capability separately.
- Anti-pattern check: pass if the envelope never becomes a universal visibility grant.
- Cost: **moderate** — common contract and rendering framework, capability-specific policies.

### 2. Context-preserving account and install handoff

- Expansion: after useful web participation, signing in or opening the app returns the recipient to the same invitation and action state.
- Job elevation: commitment becomes the next step in a real relationship rather than a restart at Kwilt's home screen.
- Anti-pattern check: pass if install remains optional until durable or native participation is actually required.
- Cost: **moderate** — universal links, deferred deep-link receipt, and explicit expired/revoked handling.

### 3. A reciprocal sender receipt

- Expansion: acquisition is not complete when the recipient clicks; the sender must visibly receive the cheer, reply, join decision, or pass.
- Job elevation: sharing becomes a closed support interaction rather than an outbound marketing event.
- Anti-pattern check: pass if the system does not manufacture urgency or public performance.
- Cost: **cheap** for existing Goal feed delivery; **moderate** for cross-capability consistency.

### 4. Friends after demonstrated value

- Expansion: once two people complete a meaningful interaction, Kwilt can quietly offer to make future sharing easier.
- Job elevation: the Friend relationship records trusted reuse without granting access.
- Anti-pattern check: pass if dismissal is quiet, friendship is optional, and no object membership is inherited.
- Cost: **cheap** after the secure Friends foundation and handoff contract exist.

### 5. Guest participation for Games

- Expansion: a future Game link can show the premise, people, time commitment, and safe guest action before requiring an account to save identity or history.
- Job elevation: people can join a playful moment without joining an administrative Household.
- Anti-pattern check: pass if a Game never reveals other Household, Friend, Goal, or child data.
- Cost: **moderate to expensive**, depending on synchronous state and abuse controls.

### 6. Paid organizer depth after repeat value

- Expansion: once the loop repeats, paid value can include richer history, structured check-ins, controllable reminders, additional ongoing relationships, family administration, or premium Games.
- Job elevation: payment deepens a working support system rather than unlocking the right to respond.
- Anti-pattern check: pass if the recipient's basic entry and response remain free.
- Cost: **moderate**, but deliberately deferred until repeat behavior is proven.

### 7. Privacy-safe growth measurement as infrastructure

- Expansion: the operational invite service produces aggregate stage counters and keeps authorization tokens separate from analytics events.
- Job elevation: Kwilt can improve the flow without building a hidden map of private relationships and content.
- Anti-pattern check: pass only if names, invite codes, object content, raw identities, and durable pair identifiers are absent from analytics.
- Cost: **moderate** — instrumentation changes, event contract, deletion/retention review, and tests.

## Frame recommendation

Use the expanded frame **Recipient Sharing Growth Loop**.

Do not frame the next work as “build a Friend landing page.” Goal already contains the strongest recipient value, and Friends works better as the retention layer after value. The system should prove one complete Goal loop first, then let Friend and Game invitations reuse its consent, handoff, and measurement contracts.
