# Yes-And: budget-app-unlock-review

## Expansion check
The offered idea is not just another Screen Time condition. It is the clearest expression of Kwilt Money's core value unit: an app opens only after the budget it can affect has been reviewed.

## Bigger surface hiding inside the request
The broader surface is an "intentional access task" that can be activated by several budget facts:

- always review first,
- running hot,
- percent threshold reached,
- over budget,
- transactions need review,
- future weekly review or recovery-plan gates.

The user does not need to learn those as separate workflows. Each should resolve into the same task contract:

1. The app is paused.
2. The relevant budget is named.
3. The reason is plain.
4. The user chooses `Open for now` or `Keep blocked`.

## Job elevation
Instead of asking "How do we let users configure blockers?", ask "How do we make the blocked-app moment the easiest possible budget review task?"

This keeps the feature from drifting into a settings product. Settings exist only to choose which app and which preset; the product value happens when the user reaches the budget and makes the opening intentional.

## Frame recommendation
Run the loop with the expanded frame: **Budget Review Unlock**.

The sprint should deliver a reductive interaction model where triggers are inputs, the budget is the review surface, and an explicit review receipt is the only unlock mechanism.
