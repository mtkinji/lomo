# Diverge: Money Transaction Notes

Axis of variation: always-visible editing vs progressive disclosure vs repurposing provider data.

## A. Inline text area
Show an editable note field directly on every transaction. This maximizes discoverability, but adds keyboard/editing weight to a screen whose main job is understanding transaction truth. It fits Maya only when notes are common and fails when most transactions need no annotation. It risks finance-dashboard clutter.

## B. Note row plus focused drawer
Show a quiet `Add a note` row, or the saved note, beneath payment-source truth. Tapping opens a bounded drawer with one labeled multiline field and Save. This keeps capture available at the moment of confusion, fits the current object-detail and drawer system, and fails only if users need rapid bulk annotation. It avoids dashboards, pressure, default-public sharing beyond the existing household, and anthropomorphic AI.

## C. Edit Description
Make the existing Description field editable. This appears smallest visually, but collapses provider evidence and household interpretation into one field. It fails the trust job because the user can no longer distinguish bank truth from a Kwilt annotation.

## Recommendation
Choose B. It adds one clear capability without weakening provider truth or crowding the detail screen.
