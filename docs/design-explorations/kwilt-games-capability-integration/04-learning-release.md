# Learning Release: Kwilt Games Capability Integration

## Concept To Build

A first-class Games destination in Kwilt containing the complete committed Games shelf and its local and remote play foundations.

## Capability Delta

Today the user cannot play a game inside unified Kwilt. After this release they can enter from Fun and use the Games product they already had: its full catalog, utility, setup, players, personal bests, audio, local sessions, joining, and remote foundations.

## User Experience

The Fun section contains `Games`. Entry opens the established playful shelf, not another Kwilt dashboard. Game, utility, profile, join, and room routes remain descendants of that shelf; Back returns within Games.

## Buildable Slice

Must be real: registry/navigation/deep-link ownership; the full committed catalog and utility; local setup, completion, replay, roster, identity, best, sound, and orientation behavior; and committed remote/join/nearby/backend paths.

Excluded as duplicate ownership: standalone Expo Router, standalone auth storage, a second Supabase client, app icon/bundle/release settings, and individual global-menu rows.

## Release Channel

Local build for Andrew-only evaluation, followed by TestFlight only after Simulator surface proof and parity review.

## Brand-Goodwill Guardrails

No sign-in gate for local play, no child data collection, no public scoring, no productivity language, and no release claim until backend/device verification catches up with source parity.

## Reversibility

Games is isolated behind one definition/root route. The capability can be hidden independently, while its additive backend tables/functions require the normal migration rollback discipline.

## Permanent Product Threshold

Simulator and family-use evidence show that entry is obvious, setup is lighter than organizing the same game manually, and the Games surface still feels playful inside the shared shell.
