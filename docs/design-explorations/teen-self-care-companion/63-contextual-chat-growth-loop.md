# Contextual Chat Growth Loop

## Learning slice

The Pet capability contains one young becoming-tree. Touching it opens the real shape of contextual Chat: the destination changes, the Pet and tree arrive as visible removable context, and Chat offers only the three useful ways already agreed for this prototype. Completing one simulated action creates a privacy-safe receipt. Returning to Moss lets the meadow, the tree, and Moss answer together.

## UI contract

- **Job:** When I notice something in Moss's world that could grow, I need help choosing one manageable action, so I can move something real forward and immediately witness what changed.
- **Primary action:** Touch the becoming-tree, choose one path in Chat, complete it, then return to Moss.
- **Must show:** The Pet/tree context; three bounded paths; the selected action; an explicit completion; **Back to Moss**; a visibly changed tree on return.
- **Reveal later:** Broader Chat composition, real To-do and Focus data, thread history, additional contextual launchers, and cross-capability policy.
- **Must not add:** A floating Chat bubble, Pet dialogue, points, currency, a growth meter, task content ingestion, a second task database, guilt, decay, or a production Chat backend.
- **Reuse map:** The existing immersive capability frame, Pet world coordinates, meaningful-action receipts, source-specific life echoes, Moss's authored discover response, and local browser persistence.
- **Behavior sources:** The user-approved Pet → Chat → action → Pet loop; the existing one-care-moment-per-day rule; capability-owned action receipts; the existing contextual Chat design direction.
- **Required states:** Resting tree, contextual Chat choice, selected action, completed action, returning/growing, already-grown-today, reduced motion, and reopened prototype state.
- **Proof path:** `/?play=1` at an iPhone-width viewport; tap the becoming-tree; select **Choose an existing To-do**; complete it; choose **Back to Moss**; observe the new tree stage, life echo, and Moss response.

## System boundary

This is a local learning release. Chat state is an ephemeral draft and is never persisted as a thread. The prototype stores only the tree's bounded growth count alongside existing Pet state. It does not read or write production Kwilt data.

## Learning question

Does a contextual Chat handoff remove the blank-prompt problem while making the return to Pet feel causally rewarding rather than transactional?
