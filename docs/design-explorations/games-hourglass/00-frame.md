# Frame: Games Hourglass

## What the user said
> I’m playing a game now and I don’t have a 60s hourglass timer, so I need one. I want it to look great, with possible optional music.

## Restated in user voice
When a game calls for a one-minute turn and the physical timer is missing, the group wants a beautiful replacement they can start immediately so play keeps moving without setup or improvisation.

## Target audience
`audience-aspirational-family-organizers`: people who want a small opening for shared play to remain easy.

## Representative persona
Maya is already at the table with family or friends and discovers the game needs a 60-second timer.

- Current situation: play has started and everyone is waiting.
- What she is trying to do: restore the missing game piece in seconds.
- Emotional state or tension: playful momentum is at risk of turning into phone fiddling.
- What would make this feel wrong: setup, accounts, ads, configuration, or a generic productivity timer.

## Hero anchor
`jtbd-help-us-enjoy-being-together` — the timer protects the shared-play moment.

## Job flow step
`job-flow-maya-start-playing-together`, steps 6–7. Kwilt already offers a Games shelf and Basic Dice Roller, but it cannot replace a missing one-minute hourglass during play.

## Active anchors
- `jtbd-help-us-enjoy-being-together` — keeps an in-progress table game moving.
- `jtbd-trust-this-app-with-my-life` — the timer must be accurate, legible, calm, and dependable.

## Friction we're addressing
The group has a game but lacks the physical one-minute timer it expects. Opening a general timer app introduces configuration and visual noise at the exact moment everyone is ready to play.

## System alignment
Constraint posture: `Fit the system`

Current system facts:
- Existing surface: Games shelf with a dedicated Utilities section.
- Existing user flow: Basic Dice Roller launches directly from a utility card without player setup.
- Existing domain/data model: utility routes are separate from the accepted multiplayer catalog.
- Existing technical affordances: Games theme, native stack, animation, haptics, completion cues, and optional game music.
- Existing UX/copy conventions: tactile table-native surfaces, guest-first entry, one obvious next action.

Constraints to preserve:
- Keep Hourglass a utility rather than inflating the game catalog.
- Begin without accounts, player seats, permissions, or settings.
- Preserve Games-owned navigation, audio policy, and visual character.

Constraints we may challenge:
- None for the first release.

Design implication:
Add one utility card and one full-screen, fixed-duration surface whose dominant action is physically metaphorical: flip the hourglass.

## Aspirational design challenge
How might we help Maya replace a missing 60-second game piece instantly, while preserving the playful momentum and tactile character of the table?

## Out of scope
Custom durations, presets, pause/resume, scores, players, remote synchronization, notifications, and a general-purpose productivity timer.

## Open question
None.
