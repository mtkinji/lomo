# Reductive UI Gates 1–2

## Gate 1 — Structural reduction

**Pass.** The automatic living plan does not earn a new destination, plan dashboard, approval step, confidence display, or persistent math card. It is consumed through existing surfaces. The normal path is target slider -> account sync -> generated Summary budgets.

Visible additions are limited to one notice when the active plan changes, one focused receipt on demand, one category source line, and one transaction meaning when inspected or materially unresolved.

## Gate 2 — Judgment reduction

**Pass with a binding constraint.** Kwilt must decide classification, category reuse, fixed-first allocation, materiality, and safe promotion. The user chooses only the living target and any deliberate category override. Exceptional money is excluded safely unless explicit intent is required to use it.

No ordinary state may ask the user to approve a candidate, interpret a confidence score, allocate a remainder, select a planning mode, or reconcile account-specific plans.

## Implementation constraint

If a proposed implementation needs persistent planner chrome to explain itself, stop and improve the receipt/provenance contract instead. Candidate machinery remains internal; active change visibility remains mandatory.
