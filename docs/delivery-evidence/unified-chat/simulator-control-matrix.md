## Findings

1. The deployed `ai-chat` gateway originally rejected internal agent calls with 401; handler-owned service-role authorization now passes behind `verify_jwt = false`.
2. OpenAI rejected dotted canonical operation IDs as function names with 400; the provider adapter now uses stable, provider-safe encoded names and decodes them back to canonical IDs.
3. The conversational authorization RPC was deployed after the functions that called it; the matching migration is now applied.
4. A completed device read originally rendered only `Completed`; the workbench now shows the bounded returned value.
5. OpenAI strict function schemas reject several semantic validation keywords used by Kwilt's canonical schemas. The provider adapter now strips `minLength`, `maxLength`, `uniqueItems`, `minProperties`, and `maxProperties` from only the provider wire copy; Kwilt's source schemas and local executor validation remain unchanged. `agent-run` 14 contains this patch, and the reviewed `goals.create` path progressed from a provider 400 to a visible pending proposal.
6. Simulator automation dropped leading or interior characters in three submitted prompts (`Create` became `Ceate`; `goals` became `ols`). This can change deterministic authorization even when model routing recovers the intended capability. Subsequent matrix commands must be visually verified in the composer before submission; input fidelity is recorded separately from backend policy behavior.
7. The companion workbench required about 20 seconds to hydrate on the first cold launch before content appeared. It recovered without intervention, so this is recorded as cold-start latency rather than a persistent blank-screen failure.
8. A proposal decision can finish while macOS locks, leaving the embedded workbench's pre-lock card on screen. The native foreground policy previously refreshed only active runs and client handoffs, so the stale proposal accepted a duplicate invalid action and surfaced the raw backend error. Foreground refresh now includes pending, edited, and deferred proposals; the workbench derives controls from the backend transition table (`deferred`: Change/Apply; `failed`: Apply only).
9. Reversible receipts outside the To-do inventory rendered no Undo action and hard-coded `Review in Plan`, including Goal receipts. Generic receipts now expose Undo while applied and use the returned object's label for the open destination. The Goal undo passed visibly and durably.
10. Imperative navigation prompts could omit the `account_navigation` namespace, so `Open Arcs` was answered as unavailable. Imperative navigation now augments the selected namespace set, and the generic capability destination contract covers all 16 included destinations. `agent-run` 15 contains this planner change.
11. Arcs navigation originally preserved a previously selected Arc detail inside the nested navigator. The canonical Arcs action now targets the Arcs list explicitly; the repeated handoff landed on the list.
12. A Chapters first-use coachmark remained visible after the user moved into Money. This cross-capability overlay leak did not block the Money destination after dismissal, but remains an open UI lifecycle defect.
13. Chores was reachable but unusable because production lacked both its Household conversational-control prerequisite and the activity-backed Chores migration. The local Chores migration also contained two SQL defects: an invalid record loop and mismatched snapshot-construction parentheses. Regression coverage now protects both shapes; the prerequisite and corrected Chores RPCs are applied remotely. The synthetic matrix user then needed canonical Household owner bootstrap data. After bootstrap, the visible retry loaded the authorized Matrix Tester Chores surface with its empty state, Add a chore, settings, and contextual Chat.
14. A later Chores assistant request exposed a distinct reliability gap: the agent accepted the run, the planning bucket returned 200, and the execution bucket returned HTTP 429 `quota_exceeded` because 27 matrix actions had crossed the configured free daily safety rail. The UI reduced this known quota condition to generic `Response interrupted`; one-click retry repeated the known failure and inserted another user message. A seven-day `simulator_control_matrix` Pro entitlement now prevents the synthetic fixture from consuming or being blocked by consumer quota limits. The product fix is deployed in `agent-run` 17 and `agent-channel-tick` 13: the known code survives the proxy boundary, the UI says `Daily Chat limit reached` and omits Retry, and `20260829174829_unified_chat_retry_message_reuse` creates a child run without inserting the parent's prompt again. Focused tests and a rollback-only production transaction proved quota classification, one-message retry, parent provenance, and duplicate-trigger replay. Visible Simulator retry remains the final proof for this finding.
15. Post-migration Supabase security advisors showed that the two Chores `SECURITY DEFINER` wrappers inherited default PUBLIC execute permission. The functions still required a permanent authenticated user internally, but the public grants were unnecessary exposure. A regression and hardening migration now revoke PUBLIC/anon/authenticated before granting only authenticated. Live REST proof is `anon=401`, `authenticated=200`; the remaining authenticated-definer advisor warning is intentional because these are actor-checking RPC boundaries.
